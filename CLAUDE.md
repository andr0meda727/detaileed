# Detaileed

pnpm + Turborepo monorepo for a car-detailing platform. UI text is Polish.

```
apps/dashboard/     studio-management SPA: React 19 + TypeScript (strict) + Vite
                    src/{app,routes,features,shared} (see docs/frontend-architecture.md), tests/ = Vitest
packages/api-client/ @detaileed/api-client: fetch layer (fetcher.ts) + React Query hooks and models
                    generated by Orval from openapi.json into src/generated (committed, never edit by hand)
packages/ui/        @detaileed/ui: design system: theme.css (Tailwind v4 @theme tokens, base styles, utilities)
                    + generic components (Button, Badge, Modal, FormInput, FormSection, Skeleton, toasts, …)
packages/domain/    @detaileed/domain: pure TS helpers shared by the apps (studioTime, vehicleSize, serviceCategory,
                    money), imported by module: `@detaileed/domain/studioTime`
packages/config/    shared tsconfig (base/react), ESLint flat config, Prettier config
docs/               plans and architecture notes
```

Dashboard stack: data from a separate .NET API; auth is Supabase; server state is TanStack React Query; forms use react-hook-form + zod; styling is Tailwind v4 via `@tailwindcss/vite` (tokens and shared styles in `packages/ui/src/theme.css`; the app's `src/index.css` only imports it). Use **pnpm** only, never npm/yarn (that would create a second lockfile).

## After every change (required)

Run these before calling a task done, and fix whatever they report:

1. `pnpm prettier --write <changed files>`: format only the files you touched. The dashboard sources haven't been fully formatted yet, so don't run `pnpm format` on everything unless asked.
2. `pnpm --filter @detaileed/dashboard exec eslint --fix <changed files>`, then `pnpm lint`. It must report **0 errors**. Don't add new warnings to files you touch, and clean up existing warnings (e.g. unused imports) in code you're already editing.
3. `pnpm typecheck`: must pass.
4. `pnpm test`: must pass. Add or update tests when you change logic.
5. `pnpm build`: run after changes to config, dependencies, routing or styles. `pnpm check` runs lint + typecheck + test + build in one go (the same thing CI runs).

Never silence a rule with `eslint-disable` or `@ts-ignore`/`@ts-expect-error` without a comment explaining why.

## Commits

- Commit after each small, self-contained change. Never bundle a whole phase or unrelated changes into one commit.
- One logical change per commit (e.g. "add dependency", "add config", "fix bug", "move files" are separate commits). File moves/renames go in their own commit, without content changes, so history and blame survive.
- Each commit should leave the app building, with lint and tests green (run the checks above before committing).
- Check `git status` before committing; stage only the files of that change (watch for leftovers already staged).
- Work on a branch (e.g. `refactor/phase-2-api-client`), not directly on `main`; pushing to `main` deploys. When a phase is done, fast-forward local `main` to it; don't push unless asked.
- Message style: short, lowercase, imperative, with an optional conventional prefix (`fix:`, `feat:`, `refactor:`, `chore:`, `build:`, `ci:`, `docs:`, `test:`).

## Commands (run from the repo root)

| Command                                        | Purpose                                                           |
| ---------------------------------------------- | ----------------------------------------------------------------- |
| `pnpm install`                                 | install all workspace dependencies                                |
| `pnpm dev`                                     | dashboard dev server on :3000 (`/api` proxied to the API)         |
| `pnpm build` / `pnpm test` / `pnpm lint`       | run across all packages via Turborepo                             |
| `pnpm typecheck`                               | `tsc --noEmit` in every package                                   |
| `pnpm check`                                   | lint + typecheck + test + build (what CI runs)                    |
| `pnpm --filter @detaileed/dashboard <script>`  | run a script in one package (e.g. `test:watch`)                   |
| `pnpm --filter @detaileed/dashboard add <pkg>` | add a dependency to the dashboard                                 |
| `pnpm format` / `pnpm format:check`            | Prettier                                                          |
| `pnpm generate`                                | regenerate the API client from `packages/api-client/openapi.json` |
| `docker build -f apps/dashboard/Dockerfile .`  | production image (build context = repo root)                      |

Env vars: see `apps/dashboard/.env.example`; local overrides go in `apps/dashboard/.env.local` (git-ignored). `VITE_API_URL` is the API **origin** without `/api` (e.g. `http://localhost:5174`; empty = Vite proxy in dev, `https://api.detaileed.com` in prod). `VITE_MAP_STYLE_URL` (empty = OpenFreeMap) and `VITE_WEB_URL` (customer site, empty = `https://detaileed.com`) are read in `shared/lib/siteConfig.ts`. New `VITE_*` vars also need adding to the Dockerfile build args and the deploy workflow.

## Code conventions (dashboard, paths relative to `apps/dashboard/src`)

- **Structure:** `app → routes → features → shared`; a feature is used by others only through its `index.ts`. ESLint enforces this (`featureSlices` in `packages/config/eslint.js`). Details: `docs/frontend-architecture.md`.
- **Server data goes through React Query hooks only**, built in a feature's `api/` on top of `@detaileed/api-client`. Never call `fetch` directly (lint error); use `apiFetch` only for endpoints that aren't in the spec yet.
- **API spec updates:** a Debug build of the backend (`detailflow-api`) writes `docs/openapi.json`; copy it to `packages/api-client/openapi.json`, run `pnpm generate`, and commit the spec and the generated code together (CI fails if they drift).
- **API data:** normalise responses in the feature's `model/` (decimals and ids may arrive as strings; money is złoty, format with `formatPln` from `@detaileed/domain/money`). Enums travel as names (`"Large"`); show them with the labels in `@detaileed/domain/vehicleSize` and `@detaileed/domain/serviceCategory`.
- **Dates and times:** the API takes and sends UTC moments and plain studio days (`yyyy-MM-dd`). Show and enter times in the **studio's** time zone (`useStudioTimeZone()` from `features/studios`), never the browser's: use `@detaileed/domain/studioTime` (`dayInZone`, `timeInZone`, `todayInZone`, `zonedToUtc`, `formatInZone`, `formatDay`). Never take a day from `toISOString()` or `new Date().getDate()`.
- **Mutation errors** are toasted globally (`shared/queryClient.ts`). Set `meta: { skipGlobalError: true }` when the caller shows the error itself.
- **UI components:** generic ones come from `@detaileed/ui` (`Button`, `Badge`, `Modal`, `FormInput`, `FormSection`, `Skeleton`, `EmptyState`, `LoadingSpinner`, `Select`, `useToast`/`ToastProvider`). Use `Button` (variants, `loading`, `icon`) instead of hand-styled buttons; its `className` is for layout only. Only app-specific UI stays in `shared/ui`. New generic components go in `packages/ui` with a test. Maps come from the separate entry `@detaileed/ui/map` (`MapView`, `MapPicker`, MapLibre); load it lazily (`React.lazy`) so MapLibre stays out of the main bundle.
- **Colours:** use the theme tokens (`green-deep`, `cream-warm`, `amber`, …; `bg-brand-gradient`), not hex values. In inline styles use `var(--green-deep)`-style variables.
- **API errors:** use `getApiErrorMessage` from `shared/lib/errorHandler.ts`. Never leave an empty `catch`.
- **Roles:** helpers in `shared/lib/studioRole.ts`; team role ids and labels in `features/team/model/roles.ts`.
- **Forms:** react-hook-form + `zodResolver`, schemas in the feature's `model/schemas.ts`. Read values with `useWatch`, not `watch()`.
- **Routing:** TanStack Router, file-based, in `src/routes` (`_auth` = signed-in layout, `_auth/s/$studioId/*` = screens inside a studio). Route files stay thin: guards in `beforeLoad`, URL state in `validateSearch` (zod), the screen from a feature's `index.ts`. Navigate with `<Link>`/`useNavigate`, never with component state. The vite plugin regenerates `src/routeTree.gen.ts`; commit it (CI fails if it's stale).
- **Current studio:** `useStudio().selectedStudio` (from the URL, set by the `/s/$studioId` layout). API calls get it from `features/studios/model/activeStudio.ts`; don't store the studio anywhere else.
- Use the `@/` alias (→ `src/`) for imports.
- Keep components under ~250 lines; split big views into smaller components.
- Derive state instead of `useEffect` + `setState` (`react-hooks/set-state-in-effect` is an error); to reset a form, remount it with a new `key`.
- Shared lint/TS rules belong in `packages/config`, not in an app's config.

## Architecture direction (re-architecture in progress)

0. Hygiene (env-based API URL, Tailwind build, ESLint/Prettier, strict TS): done

5. Shared design system in `packages/ui` (+ Tailwind v4): done
6. Public marketplace (`apps/web`, Next.js SSR/ISR)
